# 웹 이미지로 포스트 그림 보강

CLAUDE.md의 절대 규칙을 따른다. 특히 **커밋·푸시는 명시적 지시가 있을 때만** 한다.

이 블로그의 그림은 전부 `_code/<slug>/generate_figures.py`로 그린 계산 결과다. 계산으로는
그릴 수 없는 것이 있다. 글랜-테일러 프리즘이 실제로 어떻게 생겼는지, SEM 칼럼 안에 무엇이
들어 있는지, 이차전자 영상이 실제로 어떤 느낌인지 같은 것들이다. 이 스킬은 그런 빈자리를
웹의 자유 라이선스 이미지로 메운다. 목표는 그림 개수를 늘리는 것이 아니라
**본문이 말로만 설명하는 것을 눈으로 보여주는 것**이다.

스크립트 두 개를 쓴다. 경로는 `S=.claude/skills/add-web-figures/scripts`로 잡는다.

| 스크립트 | 하는 일 |
| --- | --- |
| `webimg.py` | 위키백과 문서의 그림 목록, Commons·Openverse 검색, 라이선스 등급, 출처 표기 문구, 내려받기 |
| `figures.py` | 그림 번호·캡션·출처 표기 점검, 그림 번호를 등장 순서대로 다시 매기기 |

둘 다 네트워크를 curl로 한다. 이 맥의 Python `urllib`은 SSL 인증서 검증에 실패한다.

다른 스킬도 이 스킬의 일부를 가져다 쓴다. 규칙을 고치면 그쪽에도 영향이 간다.

| 스킬 | 가져다 쓰는 것 |
| --- | --- |
| `write-post` | 새 글의 웹 이미지에 원칙 2와 2·4·5단계 적용 (6단계), `figures.py check`로 초안 점검 |
| `revise-post` | 영문판에서 `ext-*` 이미지를 다시 만들지 않기 (4단계), `figures.py check`로 검증 (6단계) |
| `research-sources` | 논문 그림을 실을 때 원칙 2 적용 (5단계) |

## 원칙 1 — 기존 글을 고치는 작업이다

CLAUDE.md 절대 규칙 4는 기존 포스트를 고치지 말라고 한다. 이 스킬은 사용자가 그림 보강을
명시적으로 요청했을 때만 쓰는 예외다. 그래서 손대는 범위를 좁게 묶는다.

- **고치는 것:** 이미지 태그와 캡션 삽입, 그림 번호 재정렬, 새 그림을 부르는 연결 문장 한 줄
- **고치지 않는 것:** 그 밖의 본문, front matter의 `date`, 파일명, 기존 그림 파일과 그 생성 코드

작업 중에 본문의 오류나 어색한 문장이 보이면 고치지 말고 보고서에 적어 사용자에게 넘긴다.
그건 `revise-post`의 일이다. 두 작업을 섞으면 무엇이 왜 바뀌었는지 커밋에서 구분되지 않는다.

## 원칙 2 — 출처 표기만으로는 쓸 수 없다

출처를 밝힌다고 사용 허락이 생기지는 않는다. 논문 그림, 제조사 제품 사진, 교재 도판은
출처를 적어도 원칙적으로 저작권자의 허락이 필요하다. 그래서 **라이선스가 재사용을 허락한
이미지만** 싣고, 그 라이선스가 요구하는 방식으로 출처를 적는다.

| 등급 | 라이선스 | 처리 |
| --- | --- | --- |
| **A** 사용 | 퍼블릭 도메인, CC0, CC BY, CC BY-SA, 미국 연방정부 저작물(NASA, NIST, NIH 등) | 캡션에 출처·라이선스를 적고 싣는다 |
| **B** 조건부 | CC BY-ND(잘라내기·라벨 번역 불가), GFDL 단독(라이선스 전문을 함께 실어야 함) | 조건을 후보 표에 적고 사용자가 정한다 |
| **C** 불가 | CC BY-NC 계열, 라이선스 표기 없음, All rights reserved, 공정이용(fair use) 파일 | 싣지 않는다. 필요하면 본문에서 링크로만 안내한다 |

**NC를 C로 두는 이유.** `_config.yml`에 AdSense 설정이 준비되어 있다. 지금은 꺼져 있지만
켜는 순간 비영리 조건을 어기게 되고, 그때 NC 이미지를 찾아 내리는 일은 번거롭다.

헷갈리기 쉬운 곳:

- **미국 국립연구소라고 다 퍼블릭 도메인은 아니다.** 연방 공무원이 만든 것만 해당한다.
  계약자가 운영하는 DOE 연구소(LBNL, ORNL, Argonne 등)의 이미지는 각 사이트의 이용 조건을 본다.
- **오픈액세스 논문이라고 다 CC BY는 아니다.** 저널이 아니라 **그 논문**의 라이선스 문구를 본다.
  arXiv의 기본 라이선스는 배포 허락일 뿐 재사용 허락이 아니다.
- **위키백과 문서에 실린 그림 중 일부는 위키백과 로컬 파일**이고, 대개 공정이용 조건으로
  올라와 있다. `webimg.py wiki`가 `[위키백과 로컬 파일]`로 표시하며, 이런 파일은 쓰지 않는다.
- **Openverse 같은 집계 서비스의 라이선스 표기**는 원본 페이지에서 한 번 더 확인한다.
- **`_references/`나 Research Library의 논문 PDF에서 그림을 잘라 오지 않는다.** 그 논문이
  CC BY임을 확인한 경우만 예외다.

저작권이 있는 그림이 꼭 필요할 수도 있다. 본문이 바로 그 그림을 분석하는 경우가 그렇다.
저작권법 제28조(공표된 저작물의 인용)가 성립할 여지는 있지만 요건 판단이 까다롭다.
이럴 때는 C등급임을 밝히고 사용자가 정하게 한다. 기본으로는 "원문 Fig. 3 참고" 같은 링크를 제안한다.

## 0단계 — 대상 확인

대상은 한 편일 수도, 시리즈나 전체일 수도 있다. **여러 편이면 먼저 선별한다.**

```bash
find _posts _drafts -name '*.md' ! -name '*-en.md' 2>/dev/null | sort | while read f; do
  printf "%-62s 그림 %s  웹 %s\n" "$(basename "$f" .md)" "$(grep -c '<img' "$f")" "$(grep -c '/ext-' "$f")"
done
```

그림 개수만 보고 고르지 않는다. 기준은 **글이 물리적 대상을 다루는가**다. 장비, 부품, 현상,
실측 영상을 다루는 글(엘립소미터 부품, 전자현미경, XPS)은 웹 이미지가 채울 자리가 많다.
최적화 알고리즘처럼 수식과 계산이 중심인 글은 이미 그래프로 충분한 경우가 많다. 억지로 넣지 말고
"해당 없음"으로 표시한다. 선별표(글, 현재 그림 수, 예상 빈자리 수, 한 줄 근거)를 보여주고
어느 글부터 할지 확인받는다.

**한 번에 한 편씩 관문 2까지 끝낸다.** 여러 편을 동시에 열어두면 그림 번호 재정렬과
커밋이 섞인다.

시작하기 전에 확인할 것:

- **파일 짝.** `_posts/<날짜>-<slug>.md`와 `-en.md`를 함께 잡는다 (작성 중인 글이면 `_drafts/`).
  영문판이 있으면 **두 판을 같이 고친다.**
- **다른 채팅이 손대고 있지 않은가.** 이 레포는 여러 채팅이 동시에 작업한다.
  `.claude/SCHEDULE.md`에서 상태가 `미커밋`인 글은 건너뛴다. 그 글을 쓴 채팅이 아직 커밋하지
  않았으므로, 여기서 손대면 그 채팅의 `post:` 커밋에 이 작업이 섞여 들어간다.
  `git status --short <두 파일>`에 무언가 찍혀도 마찬가지로 사용자에게 먼저 묻는다.
- **작업 등록.** `.claude/SCHEDULE.md`의 "작성 중" 표에 `| <slug> | 그림 보강 | <오늘> | 웹 이미지 후보 검토 |`
  한 줄을 적는다. 다른 채팅이 같은 글에 같은 작업을 벌이지 않게 하기 위해서다. 커밋이 끝나면 지운다.

## 1단계 — 빈자리 찾기

글 전체를 읽고 기존 그림부터 파악한다.

```bash
python3 $S/figures.py check _posts/<날짜>-<slug>.md _posts/<날짜>-<slug>-en.md
```

그다음 **본문이 말로만 설명하고 있는 것**을 찾는다.

| 유형 | 예 |
| --- | --- |
| 실물 | "방해석 두 조각 사이를 공기층으로 띄운다" → 글랜-테일러 프리즘 사진 |
| 장비의 겉모습과 속 | SEM 칼럼 단면, XPS 반구형 분석기, 엘립소미터 광학대 |
| 실제 관측 결과 | SEM 이차전자 영상, 실측 스펙트럼, 간섭 무늬 사진 |
| 표준 개념도 | 계산 그림이 다루지 않는 개념 (예: 광전 방출 과정, 전자총 구조) |

넣지 않는 것:

- **기존 그림과 같은 내용.** 이 블로그의 생성 그림은 본문의 수치와 맞춰져 있다. 비슷한
  웹 도판을 겹쳐 넣거나 대신 쓰지 않는다.
- **장식용 이미지.** 과학자 초상도 본문이 그 사람의 기여를 다루지 않으면 넣지 않는다.
- **영어 외 언어로 라벨이 붙은 도판.** Commons에는 같은 그림의 독일어·이탈리아어판이 흔하다.
  영어판이나 글자 없는 판을 찾는다.
- **워터마크가 있거나 가로 800px이 안 되는 이미지.** 본문 폭(600~760px)에서 흐리게 보인다.

한 편에 **1~3장**이 적당하다. 빈자리마다 적어 둔다: 위치(절 제목과 어느 문단 뒤인지),
독자가 봐야 할 것, 영문 검색어 두세 개.

## 2단계 — 후보 검색과 확인

후보 섬네일은 `_references/<slug>/web-candidates/`에 받는다. git에 올라가지 않는 곳이고,
사용자가 Finder에서 바로 열어볼 수 있다.

```bash
T=_references/<slug>/web-candidates
python3 $S/webimg.py wiki "Glan–Taylor prism" --thumbs $T/wiki         # 위키백과 문서에 실린 그림
python3 $S/webimg.py search "Glan-Taylor prism" --thumbs $T/commons   # Commons 검색
python3 $S/webimg.py search "scanning electron microscope column" --source openverse --thumbs $T/ov
python3 $S/webimg.py info "File:Glan-Taylor prism.jpg"                # 라이선스·작성자·출처 문구
```

찾는 순서는 이렇다.

1. **영문 위키백과 해당 문서의 그림** (`wiki`). 편집자들이 이미 골라 둔 그림이라 적중률이
   가장 높다. 문서 제목은 위키백과 표기 그대로 넣는다 (대시 종류까지).
2. **Wikimedia Commons 검색** (`search`). 과학 도판과 장비 사진이 가장 많고 라이선스 메타데이터가
   정확하다. `Category:` 페이지를 WebFetch로 훑는 것도 방법이다.
3. **Openverse** (`--source openverse`). Flickr 등에 올라온 CC 사진을 모아 준다. 실험실 장비 사진은
   Commons보다 여기가 많을 때가 있다. NC·ND는 스크립트가 처음부터 뺀다.
4. **미국 연방기관 갤러리** (NIST, NASA, NIH). 각 사이트의 이용 조건 페이지를 WebFetch로 확인한다.
5. **CC BY 오픈액세스 논문의 그림.** 실측 데이터가 꼭 필요할 때만. 논문은 `research-sources`
   스킬로 찾고, 논문 페이지의 라이선스 문구를 확인한다. 출판사 사이트는 봇을 막는 곳이 많다.

후보는 **섬네일을 Read로 직접 보고** 고른다. 제목과 설명만 보고 고르면 엉뚱한 그림이 걸린다.
볼 것은 네 가지다. 보여줘야 할 것이 실제로 보이는가, 라벨이 영어이거나 없는가, 워터마크가 없는가,
해상도가 충분한가.

`webimg.py`가 찍는 A/B/C 등급은 라이선스 이름만 보고 매긴 것이다. 최종 판단은 `info` 결과와
파일 페이지로 한다. `제한` 줄에 상표(trademarked)나 초상권(personality rights) 표시가 있으면
그것도 후보 표에 적는다.

## 3단계 — 후보 승인 (관문 1)

**글을 고치기 전에** 후보 표를 보여주고 승인받는다.

| # | 위치 | 보여줄 것 | 후보 | 라이선스 | 작성자 | 가공 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 2절 편광자, 그림2 뒤 | 글랜-테일러 프리즘 실물 | [File:…](https://commons.wikimedia.org/wiki/File:…) | CC BY-SA 4.0 (A) | … | 없음 |

- 빈자리마다 1순위 후보를 하나 내고, 있으면 대안을 하나 더 낸다.
- 섬네일 경로를 함께 적어 사용자가 열어볼 수 있게 한다.
- **후보를 못 찾은 빈자리도 표에 남긴다.** "A등급 후보 없음, 생성 그림으로 그리는 편이 낫다"처럼
  적는다. 억지로 채운 그림은 없느니만 못하다.
- B·C등급 후보는 조건과 위험을 명시한다.

사용자가 바꾸라고 하면 2단계로 돌아간다.

## 4단계 — 내려받기

```bash
python3 $S/webimg.py fetch "File:Glan-Taylor prism.jpg" assets/img/posts/<slug>/ext-glan-taylor-prism.jpg
python3 $S/webimg.py fetch --url <이미지 직접 URL> assets/img/posts/<slug>/ext-sem-column.jpg
```

- **파일명은 `ext-<내용>.<확장자>`.** `ext-` 접두사가 생성 그림(`figN-…`)과 웹 이미지를 가른다.
  `generate_figures.py`가 덮어쓸 일이 없고, 나중에 `grep -rn "/ext-" _posts`로 웹 이미지만 모아
  라이선스를 점검할 수 있다. `figures.py check`도 이 접두사로 출처 표기를 검사한다.
- **핫링크하지 않고 내려받는다.** 원본이 지워지거나 옮겨져도 글이 깨지지 않는다.
- 스크립트가 알아서 하는 것: 가로 1400px 이하로 줄이기, SVG를 PNG로 받기(확장자도 맞춰 준다),
  **투명 배경을 흰색으로 채우기.** 마지막 것이 중요하다. Commons의 SVG 렌더링은 배경이 투명해서
  그대로 두면 블로그 다크 모드에서 검은 글씨가 배경에 묻힌다. 생성 그림이 전부 흰 바탕이니 맞춘다.
- 800KB가 넘거나 가로 800px이 안 된다고 경고하면 `--width`를 조정하거나 다른 후보를 찾는다.
- **한·영이 같은 파일을 쓴다.** `en/` 사본을 만들지 않는다. 생성 그림은 라벨 언어가 달라 나눠 두지만,
  웹 이미지는 어느 판에나 같은 그림이 들어간다.
- 가공은 최소한으로 한다. 잘라냈으면 캡션에 적는다 (CC 조건). ND는 가공할 수 없다.

## 5단계 — 삽입 (한국어판·영문판 동시)

기존 그림과 같은 마크업을 쓴다. 영문판의 캡션 머리말은 **그 글이 이미 쓰는 것**(`Fig 1.` 또는
`Figure 1.`)을 따른다.

```markdown
<img src="/assets/img/posts/<slug>/ext-glan-taylor-prism.jpg" alt="글랜-테일러 프리즘 실물" width="600">
_그림101. 글랜-테일러 프리즘 실물. 비스듬히 보이는 경계면이 두 방해석 조각 사이의 공기층이다. (출처: 작성자, [파일 제목](https://commons.wikimedia.org/wiki/File:…), [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/))_
```

```markdown
<img src="/assets/img/posts/<slug>/ext-glan-taylor-prism.jpg" alt="A Glan-Taylor prism" width="600">
_Fig 101. A Glan-Taylor prism. The oblique boundary is the air gap between the two calcite halves. (Source: author, [file title](https://commons.wikimedia.org/wiki/File:…), [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/))_
```

**번호는 임시로 101, 102…를 붙인다.** 기존 번호와 겹치지 않는 임시 번호를 쓰면 6단계에서 스크립트가
등장 순서대로 한꺼번에 다시 매긴다. 연결 문장에서도 `그림101`로 부른다.

**출처 부분**은 `webimg.py info`가 찍어 주는 `KO:`/`EN:` 줄을 그대로 붙인다. 작성자, 원본 링크,
라이선스, 라이선스 링크의 네 가지가 CC가 요구하는 표기다. 잘라냈으면 끝에 `, 일부 잘라냄` /
`, cropped`를 더한다. 작성자 자리에 `<작성자 확인 필요>`가 찍혔으면 메타데이터에 작성자가 없는
것이다. 파일 페이지의 Author 란을 WebFetch로 읽어 채운다. "작성자 미상"으로 적당히 넘기지 않는다.
논문에서 가져온 그림이면 그 논문을 글 말미 "참고자료" 절에도 추가한다.

**캡션 설명**은 기존 캡션처럼 쓴다. 첫 문장은 무엇인지, 둘째 문장은 무엇을 눈여겨볼지다.
원본의 설명문을 번역해 옮기지 않고 자기 문장으로 쓴다. 영어 라벨이 박힌 도판을 한국어판에 넣을 때는
핵심 라벨을 캡션에서 한국어로 풀어 준다 (예: "detector가 검출기다").

**연결 문장**은 한 줄로 끝낸다. 이 블로그의 글은 "그림1은 …"처럼 그림을 본문에서 부르므로 새 그림도
불러야 한다. 기존 문장이 이미 그 대상을 말하고 있으면 문장 끝에 `(그림101)`만 붙이는 편이 낫다.
새 문장을 쓸 때는 `revise-post` 2단계의 문체 규칙(평서문, 번역투 금지, 음차 후 영문 병기)을 따른다.

**위치**는 그 그림이 답하는 내용을 본문이 먼저 꺼낸 문단의 바로 뒤다. 절 첫머리에 그림부터
두지 않는다. **폭**은 사진 600, 넓은 도판 700~760으로 기존 그림과 맞춘다. `alt`는 그림에 무엇이
보이는지를 각 언어로 짧게 적는다.

## 6단계 — 그림 번호 다시 매기기

```bash
python3 $S/figures.py renumber _posts/<날짜>-<slug>.md            # 미리보기
python3 $S/figures.py renumber _posts/<날짜>-<slug>.md --apply
```

영문판에도 똑같이 돌린다. 캡션의 등장 순서대로 1부터 다시 매기고, 본문의 `그림N`, `Figure N`,
`Fig N`, `Fig. N` 참조를 **한 번에** 바꾼다. 손으로 하면 3→4를 바꾼 뒤 4→5를 바꿀 때 방금 바꾼
4까지 5가 되는 연쇄 오류가 나기 쉽다. 그래서 스크립트를 쓴다.

미리보기에서 사람이 봐야 할 것:

- **묶음 참조.** "그림 2, 3", "Figures 3, 4 and 5", "본문 그림 가운데 3·4·5"는 첫 번호만 바뀌거나
  아예 안 바뀐다. 스크립트가 줄을 따로 모아 보여주므로 번호 대응표대로 직접 고친다.
- **다른 문헌의 그림.** "원문 Fig. 3"처럼 외부 그림을 부르는 곳이 바뀌면 안 된다.
  `⚠ 외부 문헌 그림일 수 있음`이 붙은 줄은 적용 후 Edit로 되돌린다.
- **`_code/<slug>/`.** 주석이나 README가 그림 번호를 부르면 같이 맞춘다
  (`grep -rn "그림 *[0-9]\|Fig" _code/<slug>/`).

**파일명(`fig3-….png`)은 바꾸지 않는다.** 캡션 번호와 파일명 번호가 어긋나도 괜찮다. 파일명을 바꾸면
`generate_figures.py`까지 고쳐야 하고, 원칙 1의 범위를 넘는다.

## 7단계 — 검증

```bash
python3 $S/figures.py check _posts/<날짜>-<slug>.md _posts/<날짜>-<slug>-en.md
```

번호가 차례대로인지, 부르는 번호가 실제로 있는지, 웹 이미지 캡션에 출처와 라이선스가 있는지,
작성자 자리표시가 남았는지, `http://` 링크가 있는지, 파일이 있고 800KB 이하인지, 한·영의 그림
순서가 같은지를 본다. 문제가 있으면 종료 코드 1로 끝난다.

통과하면 로컬 빌드와 htmlproofer를 돌린다 (`revise-post` 6단계와 같은 명령이고, 예약 날짜 글도
빌드되도록 `--future`를 붙인다).

```bash
export PATH="$HOME/.rbenv/shims:$PATH"
JEKYLL_ENV=production bundle exec jekyll b -d _site --future
bundle exec htmlproofer _site --disable-external \
  --ignore-urls "/^http:\/\/127.0.0.1/,/^http:\/\/0.0.0.0/,/^http:\/\/localhost/"
grep -c 'ext-' _site/posts/<slug>/index.html _site/en/posts/<slug>/index.html
rm -rf _site
```

## 8단계 — 보고와 커밋 (관문 2)

사용자에게 보고할 것:

- 넣은 이미지 목록 (위치, 파일, 라이선스, 원본 링크)
- 그림 번호 대응표 (예: 그림3 → 그림4)
- 새로 쓴 연결 문장과 캡션 원문 (한·영)
- 작업 중에 발견했지만 고치지 않은 본문 문제 (`revise-post`로 넘길 것)
- `figures.py check` 결과

커밋은 **명시적 지시가 있을 때만** 한다.

1. `git status`와 `git diff --stat`를 보여주고 확인받는다.
2. 파일을 개별로 add한다: 두 포스트 파일, 새 `ext-*` 이미지, 번호를 맞춘 `_code/` 파일이 있으면 그것까지.
   `_references/`의 섬네일은 올리지 않는다 (애초에 git이 무시한다).
3. 메시지는 `fix(post): <slug> — 웹 이미지 N장 추가`로 쓰고, 본문에 이미지별 파일명·작성자·라이선스·
   원본 링크를 남긴다. 캡션이 나중에 바뀌어도 출처 기록이 커밋에 남는다.
4. 날짜와 발행 슬롯은 바꾸지 않는다. `.claude/SCHEDULE.md` "작성 중" 표의 자기 행을 지운다.
5. 푸시 전에 확인한다: "push하면 이미 게시된 글이 바뀝니다. 진행할까요?" 푸시하면 다음 빌드
   (매일 cron)에 반영된다.

## 예외 처리

- **API가 막히면** (429, 403): 잠시 뒤 다시 하거나 WebFetch로 Commons 파일 페이지를 직접 읽는다.
  라이선스를 확인하지 못한 이미지는 쓰지 않는다.
- **모든 빈자리에서 A등급 후보가 없으면** 그렇다고 보고하고 끝낸다. 생성 그림을 새로 그릴지는
  사용자가 정한다 (그 경우는 `revise-post` 4단계의 그림 스크립트 구조를 따른다).
- **영문판이 없는 글**이면 한국어판만 고친다. 영문판을 새로 만들지 않는다.
- **이미 웹 이미지가 있는 글**이면 `grep -n "/ext-" <파일>`로 기존 것을 먼저 보고, 같은 내용을 겹쳐 넣지 않는다.
