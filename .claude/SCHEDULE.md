# 포스트 발행 일정표

여러 채팅이 동시에 글을 쓰므로 발행일은 이 파일 하나로 정한다. `_posts/`의 파일명 날짜는
이 표를 따라야 하고, 둘이 어긋나면 이 표가 맞다.

## 규칙

1. **슬롯은 격일 20:00 KST다.** 09-24부터 이어 온 간격이다. 아래 표에 적힌 날짜만 슬롯이며,
   리듬을 바꾸려면 빈 슬롯의 날짜를 고치면 된다.
2. **완성된 순서대로 가장 이른 빈 슬롯을 받는다.** 착수 순서나 시리즈 번호 순서가 아니다.
3. **완성**은 사용자가 본문을 승인했고(write-post 7단계의 완료 신호), 영문판을 함께 낼
   글이면 영문판까지 다 쓴 상태를 말한다. 그림과 코드도 끝나 있어야 한다.
   로컬 검증은 슬롯을 받아 파일명이 정해진 뒤에 한다.
4. 작성 중인 글은 날짜 없이 `_drafts/<slug>.md`에 둔다. 영문판은 `_drafts/<slug>-en.md`다.
   `_posts/`에는 슬롯을 받은 글만 둔다.
5. **본문이 링크한 글보다 앞선 슬롯은 받을 수 없다.** 링크 대상이 아직 게시되지 않았으면
   htmlproofer가 실패해 배포 전체가 막힌다.
6. 오늘 날짜의 슬롯은 받지 않는다. 내일 이후의 빈 슬롯만 받는다. 지나간 빈 슬롯은 버린다.
7. 슬롯을 반납할 때는 행을 비우고 파일을 `_drafts/`로 되돌린다. 뒤의 글을 앞으로 당기지 않는다.

## 슬롯 받는 절차

1. **이 파일을 지금 다시 읽는다.** 다른 채팅이 그사이 슬롯을 가져갔을 수 있다.
   예전에 읽은 내용을 근거로 편집하지 않는다.
2. 링크 대상의 날짜를 확인한다. 아래로 뽑은 slug마다 `_posts/`의 날짜를 보고,
   그보다 뒤이면서 가장 이른 빈 슬롯을 고른다.
   ```bash
   grep -ohE '\]\(/posts/[a-z0-9-]+/' _drafts/<slug>*.md | sort -u
   ```
3. 그 행에 slug, 제목, 한/영, 상태 `미커밋`을 적어 저장한다. 저장 직후 다시 열어
   그 행에 자기 slug만 있는지 확인한다.
4. 파일을 옮기고 날짜를 넣는다.
   - `_drafts/<slug>.md` → `_posts/<날짜>-<slug>.md`, 영문판은 `_posts/<날짜>-<slug>-en.md`
   - 두 파일의 front matter에 `date: <날짜> 20:00:00 +0900`을 넣는다 (있으면 고친다)
   - `ls _posts/ | grep <날짜>`에 자기 파일만 나오는지 확인한다
5. "작성 중" 표에서 자기 행을 지운다.
6. 받은 날짜를 사용자에게 알린다. 이 파일은 포스트와 같은 커밋에 넣고, 푸시한 뒤 상태를
   `푸시됨`으로 바꾼다. 다른 채팅의 행이 함께 커밋되어도 괜찮다.

빈 슬롯이 셋 이하로 남으면 마지막 날짜에서 이틀씩 더해 행을 늘린다.
